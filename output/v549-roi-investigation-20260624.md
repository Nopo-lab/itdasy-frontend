## 1. 한 줄 결론

현재 사진 보정은 정확한 영역을 못 찾은 경우에도 색과 위치로 대충 추정한 영역 또는 넓은 기본 영역으로 계속 보정합니다. 특히 실제 휴대폰에서도 문제가 보인 손·손톱은 PDF의 핵심 조건인 **“ROI 없음 = 보정 없음”을 지키지 않습니다.**

주의: 아래 수치는 PC 브라우저에서 얻은 진단값입니다. 사용자가 실제 휴대폰에서 확인한 결과는 **눈·눈썹·헤어는 대체로 정상, 손 피부와 네일만 실패**입니다. 따라서 PC에서만 실패한 항목을 휴대폰 실패로 확정하지 않습니다.

## 3. PC 브라우저 사진 결과

엄격한 기준은 “영역을 찾았다는 표시”가 아니라 **실제 눈·눈썹·손·손톱·헤어와 정확히 겹치는지**입니다.

| 영역 | 사진 수 | 정확히 성공 | 성공률 | 결과 |
|---|---:|---:|---:|---|
| 일반 눈 영역 | 2 | 1 | 50% | 정면 사진의 원본 좌표는 대체로 맞지만, 근접 사진은 한쪽 눈을 놓치고 위로 벗어남 |
| 눈맑게용 흰자 | 2 | 0 | 0% | 두 사진 모두 흰자 영역을 못 찾고 기본 영역 보정으로 전환 |
| 눈썹 | 2 | 0 | 0% | 정면·근접 모두 눈썹 영역 없음 |
| 손 | 3 | 0 | 0% | 실제 손 영역 대신 추정 영역 사용, 배경·장신구·소품 포함 |
| 손톱 | 4 | 0 | 0% | 투명젤·누드톤은 놓침, 진한 컬러·프렌치는 손 피부 포함 |
| 헤어 | 1 | 0 | 0% | 머리 영역을 못 찾음 |

위 표는 PC 브라우저 진단 결과일 뿐 실제 휴대폰 판정표가 아닙니다. 실제 휴대폰에서는 손 피부와 네일 실패를 우선 확정하고, 나머지는 휴대폰 스크린샷으로 다시 판정해야 합니다.

### 눈 영역에서 추가로 확인된 문제

- 정면 사진 원본 마스크 범위: `x=313~748, y=476~545` — 실제 두 눈 위치와 대체로 일치.
- 근접 사진 원본 마스크 범위: `x=168~624, y=560~641` — 실제 눈보다 위쪽이며 화면 오른쪽 눈을 놓침.
- 화면에 파란 마스크를 그릴 때 사진은 세로 전체가 보이는데 마스크는 가로를 꽉 채우는 방식으로 확대합니다. 같은 확대 방식이 아니어서 정면 사진에서도 파란 영역이 이마·관자놀이와 사진 바깥에 표시됩니다.
- 따라서 **눈 찾기 문제와 마스크 화면 표시 문제가 동시에 존재**합니다.
- 다만 휴대폰 화면은 세로 비율이라 사진 영역과 마스크 영역의 비율 차이가 PC보다 작습니다. 이 때문에 같은 표시 오류가 휴대폰에서는 덜 보이거나 정상처럼 보일 수 있습니다.

## 4. 실제 인식 도구와 연결 경로

| 영역 | 실제 사용 도구 | 만드는 방식 | 현재 상태 |
|---|---|---|---|
| 눈·눈썹·흰자 | TensorFlow FaceMesh | 얼굴 점 좌표를 이어 다각형 생성 | 얼굴 모델은 준비됨. 근접 사진 불안정, 흰자·눈썹은 결과 없음 |
| 손 | MediaPipe Hand Landmarker | 손의 21개 점 바깥선을 연결 | 도구 상태는 준비됨. 테스트 사진에서는 정확한 손 마스크가 사용되지 않음 |
| 손톱 | MediaPipe Hand Landmarker | 각 손가락 끝에 타원 5개 생성 | 실제 손톱 분리가 아니라 손가락 끝 위치 추정 |
| 헤어 | MediaPipe Hair Segmenter | 머리/비머리 픽셀 분리 | 실행 환경에서 그래픽 기능 생성 실패 |

실행 중 확인된 상태:

- 얼굴 모델: `ready`
- 손 모델: `ready`
- 헤어 모델: `failed`
- 헤어 실패 핵심: 그래픽 처리 화면을 만들지 못해 머리 분리 모델 시작 실패

이 헤어 실패는 PC 자동 조작 브라우저 환경의 그래픽 기능 문제입니다. 휴대폰에는 실제 그래픽 장치가 있어 헤어 모델이 정상 시작될 수 있으므로, 휴대폰에서 헤어가 잘 잡힌다는 사용자 관찰과 모순되지 않습니다.

## 8. 마스크 보기 문제

요구 색:

- 파랑 = 눈
- 초록 = 눈썹
- 주황 = 손
- 핑크 = 손톱

현재 문제:

- 일반 눈은 파랑이지만 사진과 다른 확대 방식으로 그려져 위치가 틀립니다.
- 눈썹·흰자·헤어는 마스크가 보이지 않습니다.
- 손톱 추정 마스크는 핑크가 아니라 초록으로 표시됩니다.
- 별도 점검 도구는 눈을 노랑, 손톱을 초록으로 표시합니다.
- `js/photo-editor/mask-qa-tool.js:26-30`의 전체 점검 목록에는 `scleraMask`, `browMask`가 빠져 있습니다.
- `js/photo-editor/mask-qa-tool.js:178-182`는 네일을 약한 보정만 허용한다고 적었지만 실제 보정 연결 규칙과 맞지 않습니다.

## 9. 원인 추정

1. **PC와 휴대폰의 그래픽 처리 환경이 다름**
   - PC 자동 조작 브라우저에서는 헤어 모델이 그래픽 화면 생성에 실패했습니다.
   - 휴대폰에서는 실제 그래픽 장치를 써서 정상 동작할 수 있습니다.

2. **PC의 가로 화면에서 사진과 마스크 확대 방식 차이가 크게 드러남**
   - 사진은 빈 공간을 남기며 전체가 보이게 표시합니다.
   - 마스크는 빈 공간 없이 화면을 꽉 채웁니다.
   - 세로형 휴대폰에서는 두 비율이 비슷해 차이가 작아질 수 있습니다.

3. **정확한 영역을 못 찾았을 때 멈추지 않도록 설계돼 있음**
   - 여러 파일에 “기본 영역으로 계속 보정”하는 길이 의도적으로 남아 있습니다.

4. **손톱은 실제 손톱 분리 모델이 아님**
   - 손가락 끝점 주변에 타원을 그리는 방식이라 길이·각도·프렌치·투명젤을 정확히 따라가기 어렵습니다.

5. **손은 손 모양 전체가 아니라 점들의 바깥선**
   - 손가락 사이와 굽힌 손, 손목 경계가 부정확할 수 있습니다.

6. **헤어 모델은 PC 환경에서 시작 자체가 실패**
   - 이후 이마 점과 어두운 색 추정으로 넘어가 벽·옷까지 영향을 줍니다.

7. **눈 마스크 화면 확대 방식이 사진과 다름**
   - 원본 마스크가 맞아도 화면에서는 이마와 사진 밖에 표시될 수 있습니다.

8. **성공 판정이 위치 정확도를 확인하지 않음**
   - 마스크 픽셀이 조금만 생겨도 “인식됨”으로 표시합니다. 실제 눈과 겹치는지 확인하지 않습니다.

- v549에서 눈 영역 확장과 손·손톱 추정 표시가 추가됐지만, 실제 사진 기준 정확도는 확보되지 않았습니다.
- 특히 화면에 “인식됨”이 보이면서 실제 위치는 틀리는 문제가 있어 신뢰도가 더 나빠졌습니다.
- 이전 버전과 숫자로 직접 비교할 자료는 없어 “새로 생긴 문제”와 “기존부터 있던 문제”를 완전히 분리할 수는 없습니다.

## 12. 최종 판정

**부분 FAIL — 손 피부·네일 FAIL 확정**

- 실제 휴대폰에서 손 피부와 네일이 영역을 놓치는 문제는 사용자가 알아차릴 수준입니다.
- 눈·눈썹·헤어의 PC 실패는 휴대폰 실패로 확정하지 않습니다.
- v549 PASS 보고서는 철회 상태를 유지해야 합니다.
- 다음 단계는 먼저 손·손톱에 대해 **정확한 ROI가 없으면 보정을 실행하지 않도록 차단**하는 작업입니다.
- 이번 조사에서는 소스 코드를 수정하지 않았습니다.
