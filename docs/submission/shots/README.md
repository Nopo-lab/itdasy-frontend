# 스토어 스크린샷 (실제 앱 화면 캡처)

`../_capture_store_shots.mjs` 가 **실제 실행 중인 앱**을 찍어서 만든다. 손으로 그린 목업이 아니다.

```bash
ITDASY_TOKEN='<스테이징 로그인 토큰>' node docs/submission/_capture_store_shots.mjs
```

| 파일 | 규격 | 용도 |
|---|---|---|
| `membership-6.7.png` | 1290×2796 | App Store 6.7" (필수) · IAP 프로모션 |
| `membership-6.5.png` | 1242×2688 | App Store 6.5" (선택) |
| `home-6.7.png` / `home-6.5.png` | 동일 | 앱 소개 스크린샷 |

## ⚠️ 아직 제출용이 아니다 (2026-07-31 기준)

`membership-*.png` 의 결제 버튼이 **"결제 준비 중"** 으로 찍혀 있다.
IAP 플러그인이 아직 설치되지 않아 `ItdasyIAP.isAvailable()===false` 라서 그렇다
(`IAP_SETUP.md` 대기 6단계 참조).

**IAP 배선을 끝낸 뒤 반드시 다시 캡처할 것.** 지금 것을 그대로 올리면
심사원이 "구매 버튼이 비활성"인 화면을 보게 된다.

## 왜 생성 스크립트를 버렸나

이전엔 `_gen_iap_screenshot.py` 가 PIL 로 가짜 결제 화면을 그렸다. 문제:

- 앱에 이미 잘 만든 멤버십 화면(`app-plan.js` + `index.html` 플랜 팝업)이 있는데 조잡한 모조품을 썼다
- 가격이 바뀌어도 이미지엔 옛 가격(₩3,900 / ₩8,900)이 **구워진 채** 남아
  랜딩·제출문서로 계속 배포됐다 — 문서만 고쳐서는 안 잡히는 지점이었다

실제 화면을 찍으면 가격·문구의 단일 진실원이 앱 코드 하나가 된다.
