## 📋 붙여넣는 프롬프트

> 아래를 그대로 복사하고 **맨 윗줄 `대상:` 만** 바꿔서 쓴다.

```
대상: <기능 이름 — 예: 댓글 문의 응대 / 작업실 캡션 / 예약 관리 / DM 자동응답>

이 기능을 전수 QA 해줘. 순서대로, 건너뛰지 말고.

[0] 먼저 .ai/APP_FEATURE_INDEX.md 에서 이 기능 항목을 읽어. 없는 기능을 만들거나
    이미 있는 걸 다시 만들지 마. 관련 파일(FE/BE)을 먼저 특정하고 시작해.

[1] 화면에 보이는 것을 전부 목록으로 만들어. 버튼·토글·입력칸·칩·탭·링크·배지·빈 상태까지.
    "안 보이는 것"도 적어 — 코드엔 있는데 화면엔 진입로가 없는 것(고아 기능).

[2] 각 항목마다 "눌렀을 때 뭐가 나와야 정상인지"를 한 줄로 먼저 적어.
    내 앱을 모르는 사람 기준으로. 이걸 안 적으면 그냥 "동작함"으로 넘어가게 된다.

[3] 실제로 태워봐. 추측 금지. 증거 없는 "정상"은 보고하지 마.
    - 로컬 실브라우저로 진짜 클릭/입력해서 확인 (설정법은 아래 참고)
    - 서버가 끼면 curl 로 상태코드·소요시간 실측
    - 못 태운 항목은 "미검증"이라고 분명히 적어. 된 척하지 마.

[4] 항목마다 4축으로 점검:
    · 동작 — 기대대로 나오나? 빈 데이터/많은 데이터/긴 글자에서도?
    · 오류 — 실패하면 원장이 원인을 알 수 있나? 콘솔 에러 0인가?
             재시도로 돈(LLM)·시간을 태우진 않나?
    · 시간 — 몇 초 걸리나? 3초 넘으면 로딩 표시가 있나? 가짜 데이터가 먼저 뜨진 않나?
    · 보안 — 남의 데이터가 보이나? 토큰/키가 화면·URL·로그에 새나?
             innerHTML 에 사용자 입력이 이스케이프 없이 들어가나?
             발송류(DM·댓글·인스타 발행)가 원장 확인 없이 나가진 않나?

[5] 찾은 것을 플랜으로 정리. 심각도 순(고장 > 데이터 유실 > 오해 유발 > 불편 > 미관).
    각 항목에 [증거] [원인] [고칠 파일] [위험도] 를 붙여.
    고치기 전에 이 플랜을 나한테 먼저 보여줘.

[6] 승인하면 하나씩 고쳐. 한 번에 하나. 고칠 때마다:
    - 실브라우저로 재검증하고 증거 남기기
    - 회귀 확인(고친 것 옆의 기능이 안 깨졌나)
    - 커밋은 "왜" 를 남기기(무엇을 고쳤나 말고, 왜 그게 문제였나)

[7] 마지막에 .ai/APP_FEATURE_INDEX.md 의 해당 항목 갱신.

규칙:
- 못 고친 것·미검증은 반드시 보고에 남겨. 조용히 빼먹지 마.
- 내가 지적한 게 틀렸으면 근거를 대고 반박해. 맞다고 해놓고 딴 걸 고치지 마.
- 저위험(문구·색·안내)은 알아서 고치고, 고위험(발송·결제·DB스키마·권한)은 먼저 물어봐.
```

## 🔧 검증 환경 세팅 (매번 이대로)

```bash
# 로컬 서버 — CORS 허용 포트만 됨 (5500 / 8000 / 3000 / 127.0.0.1:5500)
python3 -m http.server 5500
```

브라우저 콘솔에서:
```js
// 스테이징 백엔드로 붙이기 — ?api=staging 없으면 localhost:8000 을 본다
location.href = 'http://localhost:5500/?api=staging'

// 로그인 토큰 주입 (원장 계정에서 뽑아온 값)
localStorage.setItem('itdasy_token::staging', '<토큰>')

// 🚨 검증 전 항상 — 안 지우면 옛 코드를 보고 "안 고쳐졌다"고 오판한다
for (const r of await navigator.serviceWorker.getRegistrations()) await r.unregister();
for (const k of await caches.keys()) await caches.delete(k);
location.reload();
```

서버 쪽 실측:
```bash
T='<토큰>'; B=https://itdasy-backend-staging-644329093453.asia-northeast3.run.app
curl -s -o /dev/null -w "%{http_code} %{time_total}s\n" -H "Authorization: Bearer $T" "$B/<경로>"
```

## ⚠️ 검증할 때 반드시 아는 함정 (여기서 시간 다 버렸다)

### 캐시
- **`?v=` 는 이제 배포가 자동으로 올린다**(2026-07-23~). 손으로 안 올려도 된다.
  단 **`?v=` 가 아직 안 붙은 새 파일**은 한 번 손으로 붙여야 한다.
- 그래도 **로컬 검증에선 SW 를 직접 지워야 한다**(위 스니펫). 안 지우면 옛 파일을 본다.
- "고쳤는데 화면이 그대로" → 코드보다 **캐시부터** 의심.

### 헤드리스 브라우저 한계
- `requestAnimationFrame` 이 멈출 수 있다 → `is-open` 클래스가 안 붙는다.
  **`aria-hidden` 이나 상태 객체로 판정**할 것. rAF 의존 검증은 `setTimeout` 으로 우회.
- 뷰포트가 `0x0` 이면 레이아웃이 안 잡힌다 → `resize_window` 로 mobile(375×812) 잡고 시작.
- 파일 선택(input[type=file])은 `DataTransfer` 로 넣고, **전송 버튼까지 눌러야** 업로드가 돈다
  (pending 큐 구조라 change 이벤트만으론 안 탄다).

### LLM(잇비·캡션)
- Vertex AI 쿼터가 얇다. **테스트로 연타하면 쿼터가 마른다** — 원장 실사용까지 막힌다.
  성능 측정은 **간격을 두고 2~3회만**. 결과가 429 면 쿼터지 코드 문제가 아니다.
- 규칙 기반으로 즉답되는 질문("오늘 예약")은 LLM 을 안 탄다 → **LLM 속도 측정에 쓰면 안 된다**.
  `/ai-health` 의 `fallback_stats` 가 안 움직이면 Gemini 를 안 부른 것.
- 작업실 캡션은 `/caption/generate` 가 아니라 **`/persona/generate`** 다. `category` 는 enum
  (`extension|nail|hair|makeup|skincare`) — 딴 값 주면 422 라 오진하기 쉽다.

### 자주 나온 진짜 원인 패턴
- **래퍼를 안 타는 직접 호출** — `_client` 를 직접 부르면 폴백/타임아웃 정책을 건너뛴다.
  새 호출부는 반드시 공용 함수(`_gen_sync`/`_gen_async`, `window.apiFetch`) 경유.
- **필터가 과하게 먹음** — 사담 제거 필터가 시술명까지 지워 빈 값이 되는 경우.
  (예: `재방문 고객 감사합니다` → 전부 필터 → 빈 제목)
- **경로가 둘인데 한쪽만 고침** — 예: 사진 투입이 `addPhotoFiles`(파일선택)와
  `addPhotoUrls`(채팅·딥링크) 둘이다. 한쪽만 고치면 다른 쪽에서 안 먹는다.
- **정규식이 데이터를 깬다** — `0.15mm` 가 `.` 구분자에 쪼개져 `15mm` 가 된 사례.
- **오버레이 뒤로가기 미등록** → 안드로이드 back 에서 **앱이 꺼진다**.
  새 풀스크린은 `_registerSheet`/`_markSheetOpen`/`_markSheetClosed` 필수.

### 놓치기 쉬운 축
- **PC 폭(≥768px)** — 고정 사이드바에 왼쪽이 잘리는지. `style-responsive.css` 등록 필요.
- **빈 상태** — 데이터 0건일 때 "없음"과 "못 불러옴"이 구분되나?
  (구분 안 되면 원장이 "고장났다"로 읽는다)
- **가짜 데이터** — 로딩 중에 예시/시드 데이터가 진짜처럼 뜨진 않나?
- **아이콘 규칙** — UI 는 Lucide SVG 만. 이모지 금지(스티커는 예외, 콘텐츠라서).
